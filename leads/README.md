# Lead engine

Find local churches with weak or missing websites, build each a free preview, and draft a personal email.

```bash
cp .env.example .env               # add SERPAPI_KEY
npm run leads:pull                 # Google Maps via SerpApi → leads/data/leads.csv
npm run leads:score                # audit every site → leads/data/scored.csv (best leads first)
npm run leads:preview -- --top 10  # churches/<slug>/ previews + REVIEW.md checklists
#   ...ask Claude Code to polish each preview, build and push (CI deploys <slug>.<domain>)
npm run leads:emails               # leads/data/emails/<slug>.txt + outreach.csv tracker
```

**Cost control.** Each town × query × page is one SerpApi search. The default (40 towns, "church",
1 page) is 40 searches. `--deep` adds 10 denomination queries (400 more). Responses are cached in
`leads/data/cache/`, so re-running is free. Start with `--towns "Hamilton, NJ" "Ewing, NJ"`.

**Scoring.** Points per problem, highest first: no website (150), site down (80), not mobile-friendly
(30), no HTTPS (25), no service times on the home page (25), slow (15), no giving link (15), old
copyright year (15), no contact info (10). The top 3 problems go into the email in plain English.

**Sending rules** (from the plan, and CAN-SPAM):
- About 20–30 emails a week, from your own domain, each one read and personalized by you.
- Every email has your business mailing address and an opt-out line (built into the drafts).
- Follow up once after 5 days, then stop.
- Anyone who opts out: add their email to `leads/data/opt-outs.txt`; drafts skip them.
- Remove a preview if a church asks (delete its folder and the Cloudflare project).

`leads/data/` is git-ignored: it holds contact details and is regenerated by the scripts.
